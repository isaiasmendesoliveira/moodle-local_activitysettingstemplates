# Contributing

Thank you for your interest in contributing to **Activity Settings Templates**.

## Development process

1. Fork the repository.
2. Create a focused topic branch.
3. Keep code, comments, and developer-facing documentation in English.
4. Follow the official Moodle coding style.
5. Keep user-facing changes accessible and responsive.
6. Add or update tests when behaviour changes.
7. Run relevant Moodle Plugin CI checks before opening a pull request.
8. Open a pull request with a concise description of the change and how it was tested.

## Reporting bugs

Please include:

- Moodle version;
- PHP version;
- database type/version when relevant;
- plugin version;
- activity/resource type affected;
- exact steps to reproduce;
- expected result;
- actual result;
- debugging output when available.

Do not include passwords, access tokens, personal learner data, or other sensitive information.

## Feature requests

Describe the teacher workflow or cognitive/administrative problem first, then the proposed behaviour. This helps keep the plugin focused on safe, teacher-centered improvements rather than adding settings without a clear use case.

## Security issues

Do not report security vulnerabilities in a public issue. Follow [SECURITY.md](SECURITY.md).
